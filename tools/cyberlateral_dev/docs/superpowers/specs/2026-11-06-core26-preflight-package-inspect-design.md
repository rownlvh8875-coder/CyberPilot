# CORE26 Saved preflight report inspection

Builder-selected small offline increment under delegated execution and repeated
approval opt-out. Verify a CORE25 three-file folder against an explicitly supplied
original ZIP/full SHA,without writing/extracting/replaying it.

## Approaches

Checksum-only verification cannot detect a coherently altered report. Chosen:
regenerate exact CORE21/23 JSON/Markdown from the verified original ZIP and compare
all three saved files. A standalone arbitrary JSON schema/reader would duplicate
owned report validation and cannot independently establish the original ZIP link.
Reuse unchanged CORE18 directory/layout/bounded-file capture and CORE23 report.

## API

`integration_tools.core_sequence_preflight_inspect.inspect_preflight_report(
input_root: Path, input_archive: Path, expected_sha256: str)->dict`.

1. CORE13 `_expected` checks full lowercase64hex SHA before caller path work;
   preserve ArchivePreflightError('ARCHIVE_PREFLIGHT:'+PortableError.code).
2. CORE18 `_directory`/CORE12 `_path` validate a nonsymlink root with exactly three
   regular members PREFLIGHT.json,SUMMARY_KO.md,SHA256SUMS.txt. No source file read
   before root/layout qualification; directory stays open throughout verification.
3. CORE23 `report_preflight_archive` once: original ZIP capture/verifier once,
   owned CORE21 semantic preflight and renderer once. Validate current status0/1.
4. Prepare unchanged canonical JSON,unchanged MD,sorted two-entry checksum self
   excluded. CORE18 `_read_file` reads each saved member once,nofollow/nonblocking,
   regular-file and max-size before read,cap+1 bounded reading,exact expected bytes.
5. Compare open root fd dev/inode with final path lstat; changed root rejects.
   Reused directory context validates exact layout/types before and after.
6. Return path/time-independent receipt only on complete success.
