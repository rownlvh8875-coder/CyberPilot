## Intent and approach

R59 fixed a measured mobile footer overflow. Its actual-browser regression is
currently external evidence, copied into recovery guides rather than maintained
as a normal source command. Add an explicit repository command that reproduces
the bounded sign/resumed check without needing a notebook or old evidence folder.

Selected: a separate cloud-tooling command with an already installed host
Playwright/Chromium and a separately supplied existing app Python. Record actual
browser/library versions; do not silently install or download dependencies.
Alternatives: making browser downloads part of default CI introduces unrelated
dependency/network cost; retaining only temporary scripts leaves the check hard
to repeat. Neither is selected. No default workflow or lock changes.

## Contract

`browser_smoke.py --component PATH --app-python PATH --browser PATH --output NEW`
uses only the component's existing sign/resumed portable fixture bytes and
`project/scenario_report_fixture.py` declared test receipt utility. Render each
with the existing R32 CLI in the app interpreter. No model, native, F61, r/dt,

Serve only the generated HTML, VIEW and checksum bytes from an in-memory
allowlist on an ephemeral loopback HTTP port. Block other browser requests;
do not use file URLs or modify browser policy, DOM, CSS or renderer output.
Check sign/resumed at 320/360/390/425/1440px, DPR1: exact page fit and actual pan0,

Use explicit validation, not assertions, for verdicts. Pure tests cover verdict
classification and local-server boundaries without importing Playwright. Real
browser runs are separate, explicit and mandatory for this delivery, never a
silently skipped default-CI test. A negative-control copied renderer restoring
