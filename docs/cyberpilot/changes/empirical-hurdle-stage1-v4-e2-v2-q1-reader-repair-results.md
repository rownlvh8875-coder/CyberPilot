## Numerical contract feasibility and next approval

Q1 still requires float64 dtype/shape/original-order/raw-byte equality including
signed zero. This observation fails that requirement. Equal projected ticks do
not repair continuous-delta equality: D2's continuous SSE/SAE objectives and
guards depend on those deltas. No D2 loss comparison was executed here.

Batch-independent output equality is not guaranteed by the current NumPy/BLAS
path. The observed failed job is a counterexample to universal A/C equality;
one job cannot certify the other 31 jobs. For any row with unequal A/C bit
patterns, one batch-independent output cannot be identical to both patterns.
Neither path was demonstrated to be more accurate. Q3 would use the D2-selected mask, which may differ from D0, and may
encounter the same problem. No Q3 was run.

Keeping the existing Q1 is valid as a strict stop condition; it does not enable
this E2 execution to continue. A canonical fixed-reduction kernel is a possible
future design, but can change original D0/D1 deltas, continuous losses and ticks
near rounding boundaries. It would require a separate numerical-source/policy
contract, same-anchor D0/D1 comparability qualification and fresh E2 approval.
Changing the equivalence definition also requires a separate frozen contract
covering continuous loss, not only projected tick equality. Neither remedy was
implemented or adopted. A universal cache preserving arbitrary original BLAS
selected-mask bytes is **NOT_PROVEN**; no convenient layout or mask was selected
after observing the result.
