# Carrot Long 파라미터 분류와 호출 근거 — Step 4

분석 revision: carrot2-v6 / c57d0ff11f766b7fd70e9a9eaec1247b623ffbea.
[상위 설계](../../CYBER_LONG_DESIGN.md),
[정확한 소스/AST inventory](CARROT_LONG_SOURCE_INVENTORY.json)를 함께 읽는다.
이 문서는 parameter 활성화/AutoTune/vehicle calibration 승인이 아니다.

## 1. 분류, 범위와 해석 규칙

| 번호 | 분류 | 사용 규칙 |
| --- | --- | --- |
| 1 | 차량 물리특성 | 차량/firmware별 식별; 사용자 취향과 분리 |
| 2 | 제어기 parameter | 단위, downstream error 정의와 update rate가 같아야 함 |
| 3 | 사용자 취향 | 선택은 사용자 소유; 학습기가 선호를 임의 변경하지 않음 |
| 4 | 안전 제한 또는 권한/보호 제약에 결합된 값 | enforcement와 preference를 구분하고 변경 금지 |
| 5 | 환경/상황 적응값 | source/time/confidence/reset 근거가 필요한 관측 상태 |
| 6 | AutoTune 연구 후보 | offline 후보라는 뜻; 지금은 모두 disabled |
| 7 | AutoTune 금지 | safety/authority/user policy/미확인 값; optimizer에 write 권한 없음 |

복수 분류를 허용한다. 6은 자동 적용 허가가 아니다. initial 버전은 online/offline
tune 모두 실행하지 않는다. bounds/rate/confidence 미정은 reject이며 무한 허용이 아니다.
숫자 비교로 조정할 수 있어 보여도 enum/CAN ID/array index/sentinel은 tuning knob가 아니다.

조사 범위: 선택한 core/helper와 13 brand의 interface/carcontroller/carstate/
radar_interface/values/CAN Python 파일 108개, 추가 apilot.json/params.cc/
log.capnp/car.capnp 4개. 매 파일 blob, 함수 line, 189개 Params read/write
site, 330개 longitudinal/physical/actuation field assignment를 inventory에 남겼다.
정확한 site 개수는 JSON이 기준이다. 이 scope 밖 다른 UI/admin 코드나 모든 firmware
분기를 exhaustive runtime audit했다고 주장하지 않는다.

아래 146 key는 **발견 key + manager default + settings UI key의 합집합**이다.
따라서 lateral/admin/default-only도 포함된다. 그 항목은 분류 7로 경계 밖임을
명시하고 longitudinal 구현으로 추정하지 않는다. 각 read/write를 구분하며
manager default만 있는 것은 활성 제어 기능의 근거가 아니다.
원격/장치의 실제 Params 값을 읽거나 변경하지 않았다.

## 2. 기본값과 runtime 변경의 실제 경계

- manager.py default는 key가 없을 때만 초기화한다. 기존 persistent 값은 다를 수 있다.
- apilot.json min/max/default/unit는 UI metadata다. unit는 대개 widget 증가 단위이지
  SI 물리 단위가 아니다. UI bounds를 validated safety/AutoTune bounds로 복사하지 않는다.
- CarrotPlanner constructor 임시 defaults, manager defaults, UI defaults가 서로 다르다.
  gap2/3 constructor=1.3/1.45 s, manager=1.2/1.4 s; accel constructor=
  [1.6,1.2,1.0,0.8,0.7,0.6], manager=[2.0,1.6,1.3,1.1,0.95,0.8] m/s².
  StopDistance constructor=6 m, manager=5.5 m, UI default=6 m.
  이 세 가지 중 하나를 실제 운행값이라고 단정하지 않는다.
- DT_MDL=0.05 s에서 planner count 100은 약 5 s. gap은 count20, accel30,
  stop/brake40에서 갱신되므로 한 cycle에 서로 다른 설정 generation이 섞일 수 있다.
- LongControl count100은 DT_CTRL=0.01 s 기준 약 1 s. stopping key는 100,
  gain은 10에서 읽는다. gain override는 singleton kpBP/kiBP일 때만 적용된다.
- VCruise update_params는 frame%10, Hyundai controller frame%50.
  CarrotServ update_params는 update_navi tick. CarrotMan loop는 10 Hz.
- RadarReactionFactor는 Track constructor에서 읽는다. runtime key 변경만으로
  기존 모든 track의 reaction이 동시에 바뀌지 않는다.
- LongActuatorDelay는 planner publish helper에서 매 호출 읽는다.
  CP delay와 불일치할 수 있고 UI의 zero 허용은 division 경로의 안전 보장이 아니다.
- SoftHoldMode는 default/registry에는 있으나 스캔한 runtime 호출에서 read가 없다.
  실제 Hyundai soft_hold_mode는 AutoCruiseControl>1 여부로 정해진다.
- CruiseButtonTest1/2/3은 실제 Hyundai CAN button-spam 경로에서 읽는다.
  이름이 Test라고 해서 inactive 또는 unit-test 전용 값이 아니다.
- Params registry PERSISTENT는 저장 정책이지 bounds나 기능 효과 검증이 아니다.

## 6. AutoTune 허용 후보와 금지의 실질적 차이

현재 source key 중 잠재 offline 연구 후보로 표시한 것은 LongActuatorDelay,
LongTuningKpV/KiV/Kf, RadarReactionFactor다. 이것이 이 key를 Cyber에 복사하거나
live Params로 연결한다는 뜻은 아니다. delay는 차량별 physical estimate로,
gain은 최신 controller error/단위에 맞춰, reaction은 perception 별도 연구로 재정의한다.

안전 제한, min headway/stop distance/comfort-brake constraint, FCW/confidence/freshness
acceptance, CAN topology/UDS/safety flags, engage/resume/hold/brake/cancel/DM policy,
사용자 취향과 unknown 항목은 모두 자동 변경 금지다.
학습된 gain/delay가 bounds 내부여도 위험한 closed-loop behavior를 만들 수 있으므로
replay → simulation → shadow와 별도 승인이 필요하다.

registry는 exact vehicle/firmware/model/config identity와 immutable epoch로 연결한다.
min/max/rate/confidence가 확정되지 않으면 activation을 거부한다. raw persistent key
polling과 partially updated parameter set을 제어 hot path에 추가하지 않는다.
